# WideAgent 내부 문서

사용자가 알아야 할 내용은 [README](../README.md) 에 있다.
이 문서는 **왜 이렇게 만들었는지**를 남겨 둔 기록이다.

## 배경

앱 본문 폭은 `<html>` 의 `data-transcript-width` 속성으로 정해진다.

| 값 | 본문 폭 |
|---|---|
| `s` | 약 840px (기본값) |
| `m` | 중간 |
| `l` | 1280px |

`m` / `l` 은 앱 CSS에 이미 정의되어 있으나 설정 UI로 노출되지 않고, 창 크기와도 무관하게 `s` 로 고정된다.
localStorage(`omelette-*`)에도 관련 키가 없어 사용자 설정으로 바꿀 방법이 없다.

이 프로그램은 DevTools Console에 코드를 붙여넣어 그 값을 `l` 로 바꾼다.
**앱 파일은 건드리지 않는다.** 사람이 직접 키를 누르는 것과 동일한 방식으로만 동작한다.

## 동작

1. Claude 또는 ChatGPT 실행을 1초 주기로 감지
2. 뜨면 2.5초 대기 (페이지가 자리 잡을 최소한의 여유)
3. Claude는 메인 창 활성화 → `Ctrl+Alt+I` 로 DevTools 열기 → **화면 밖으로 이동**
4. `Ctrl+Shift+P` → 검색창 전체 선택 → `>Show Console` 붙여넣기 → Enter
5. 코드 붙여넣기 → Enter
6. `copy(...)` 로 결과를 클립보드에 꺼내 **실제로 적용됐는지 확인**
7. 확인 실패 시에만 `allow pasting` 으로 차단을 풀고 재시도
8. DevTools 닫고 메인 창으로 포커스 복귀

전체 1.9초 안팎이다. 단계별 소요 시간은 로그에 남는다.

```
front=11ms devtools-open=357ms settle=163ms dev-front=123ms fast=520ms close=90ms
```

### ChatGPT 지원

ChatGPT Windows 프로덕션 앱은 DevTools 단축키를 비활성화하므로 Claude와 같은 키보드 주입을
사용할 수 없다. ChatGPT 적용을 선택하면 프로그램이 현재 실행 파일을 기억한 뒤 기존 ChatGPT
프로세스를 닫고, `127.0.0.1` 에만 연결되는 임시 CDP 포트로 다시 시작한다. 연결이 준비되면
`--thread-content-max-width` CSS 변수를 적용하고, 앱은 같은 방식으로 계속 실행된다.

재시작 중에는 ChatGPT 창이 잠시 닫혔다가 다시 열린다. 로컬 포트 번호는 프로그램 폴더의
`WideAgent.chatgpt.port` 에 저장되며, 다음 적용에서는 앱을 다시 시작하지 않고 기존 연결을
재사용한다. 포트는 외부 주소에 바인딩하지 않는다.

#### 어느 페이지에, 그리고 정말 먹었는지

CDP 목록에는 대화창만 있지 않다. 대화 안에 끼는 인라인 시각화 샌드박스(`innerWidth` 가
1px 이다), 아바타 오버레이, 분리 창이 함께 떠 있고 순서도 그때그때 다르다. 예전에는
목록을 돌다가 **처음 성공한 페이지에서 멈췄는데**, 샌드박스가 앞자리를 차지한 뒤로는
1px 짜리 페이지에 폭을 넣어 놓고 성공했다고 보고하게 됐다. 로그에는 `OK` 가 찍히는데
대화창은 그대로였다. 이제는 멈추지 않고 전부 돈다.

더 큰 문제는 **코드가 실행된 것과 폭이 변한 것을 구별하지 못했다**는 점이다. 없는 CSS
변수에 값을 넣는 것은 오류가 아니라 무시다. ChatGPT가 변수 이름을 바꾸면 주입은 멀쩡히
성공하고 화면만 그대로인 상태가 되는데, 반환값만 보는 방식으로는 알 수가 없다.

그래서 적용 코드가 **폭을 직접 잰다.** 요청한 폭을 숨긴 요소에 먹여 px 로 풀어 둔 뒤
(`min(2400px,80vw)` 같은 값도 이렇게 해야 비교할 수 있다), 그 폭을 쓰는 요소가 문서에
몇 개인지 적용 전후로 세어 늘어났을 때만 성공으로 본다. 결과는 세 가지다.

| 결과 | 뜻 |
|---|---|
| `L1` | 알려진 이름(`--thread-content-max-width`)으로 넓어진 것을 확인 |
| `L2` | 그 이름이 안 먹어, 스타일시트에서 찾아낸 이름으로 넓어진 것을 확인 |
| `blind` | 대화창은 맞는데 잴 것이 화면에 없었다. 넣어 두기는 했고 확인은 못 했다 |

`L2` 는 스타일시트의 모든 커스텀 속성 중 이름에 `max` 와 `width` 가 들어가고
`thread|conversation|chat|message|content` 에 걸리는 것을 긁어모아 전부 거는 방식이다.
ChatGPT가 변수 **이름만** 바꾸고 구조를 유지하면 여기서 살아난다. 다만 이 경로로
살아났다는 것은 앱이 바뀌었다는 뜻이므로, 찾아낸 이름을 로그에 남기고 풍선 알림을
한 번 띄운다. 알림을 클릭하면 로그가 열린다. 사용자에게는 예고이고, 고치는 사람에게는
돌아올 신호다. 조용히 넘어가면 다음 변화 때는 아무 단서 없이 죽는다.

`blind` 를 실패로 보지 않는 이유는, 대화창이 비어 있는 순간이 실제로 있기 때문이다.
그때 실패를 알리면 멀쩡한 창을 두고 경고를 띄우게 된다.

ChatGPT 전용 1회 적용은 다음과 같이 실행할 수 있다.

```
WideAgent.exe --chatgpt
```

재시작 시점을 늦춰야 하면 밀리초 단위 지연을 붙인다.

```
WideAgent.exe --chatgpt --delay=10000
```

#### 재시작 없이 쓰기 (권장)

`--remote-debugging-port` 는 Chromium이 **시작할 때만** 읽는 스위치다. 이미 떠 있는
프로세스에 CDP를 나중에 켜는 방법은 없고, 플래그를 달아 두 번째 인스턴스를 띄워도
Electron 단일 인스턴스 락 때문에 새 프로세스는 기존 프로세스에 인자만 넘기고 즉시 끝난다.
그래서 "재시작을 없애는" 것이 아니라 **처음부터 플래그를 달고 뜨게** 해야 한다.

트레이 메뉴의 **ChatGPT 넓게 실행 바로가기 만들기** 가 바탕 화면에 `ChatGPT (Wide)` 를
만든다. 이걸로 열면 WideAgent가 ChatGPT를 직접 띄우므로 껐다 켜는 일이 없다.
작업 표시줄이나 시작 메뉴에 고정해 두고 기존 ChatGPT 아이콘 대신 쓰면 된다.

```
WideAgent.exe --launch-chatgpt
```

| 경로 | 소요 | 창 깜빡임 |
|---|---|---|
| `--launch-chatgpt` (바로가기) | `launch=2.2s cdp-apply=0.4s` | 없음 |
| 일반 실행 후 적용 | `restart=9.2s cdp-apply=0.3s` | 있음 |

바로가기의 대상은 `ChatGPT.exe` 가 아니라 `WideAgent.exe` 다. ChatGPT는 MSIX 패키지라
실행 파일 경로에 버전이 박혀 있어서(`WindowsApps\OpenAI.Codex_<버전>_x64__<해시>\app\`)
업데이트마다 바뀐다. 경로 해석은 실행할 때마다 다시 하며, 순서는

1. 돌고 있는 ChatGPT 프로세스의 실행 파일 경로 (가장 확실하다)
2. `WideAgent.chatgpt.exe.txt` 캐시 — 1에서 본 값을 적어 둔 것
3. `Get-AppxPackage` 로 Windows에 직접 질의

이다. 폴더 목록에서 제일 높은 버전을 고르는 방법은 쓰지 않는다. `WindowsApps` 에는
아직 등록되지 않은 다음 버전이 미리 내려받아져 함께 놓여 있을 수 있어서, 최신 폴더가
지금 실행되는 버전이라는 보장이 없다.

시작 메뉴의 원래 ChatGPT 항목은 편집할 수 없다. MSIX 앱은 `.lnk` 가 아니라 AUMID 로
실행되고, 그 경로로는 명령줄 인자를 붙일 방법이 없다. 원래 아이콘으로 열면 플래그가
없으므로 기존 동작(껐다 켜기)으로 되돌아간다.

### 지름길

DevTools는 마지막에 쓰던 패널을 기억한다. 우리가 항상 Console로 끝내므로,
다음에 열면 이미 Console이라 커맨드 메뉴(약 900ms)를 통째로 건너뛸 수 있다.
로그의 `fast=` 가 이 경로다. `console=` 이 보이면 지름길이 실패해 폴백을 탄 것이다.

단, **우리가 직접 연 창이고 `WideAgent.state` 기록이 있을 때만** 쓴다.
Elements 패널에 코드를 붙여넣으면 DOM에 노드가 삽입되기 때문에 함부로 생략하면 안 된다.

### 대기 시간의 한계

측정으로 바닥을 찾았다. `settle`(창이 뜬 뒤)과 `dev-front`(포커스 이동 뒤)는
DevTools가 입력을 받을 준비가 되는 시간이라 줄이면 안 된다.
각각 100ms/60ms로 낮췄더니 지름길이 10번 중 8번 실패해 폴백을 타면서
오히려 평균 3.55초로 느려졌다. 160ms/120ms 가 안전한 하한이다.

### 검증

키를 다 보냈다는 것과 코드가 실제로 돌았다는 것은 다르다. 확인 없이 대기 시간을 줄이면
깨져도 알 수가 없다. 그래서 적용 후 콘솔에 `copy(document.documentElement.dataset.transcriptWidth)`
를 실행해 값을 시스템 클립보드로 꺼내 읽는다. 값이 `l` 이어야 성공이다.

> `document.title` 에 표식을 남기고 창 제목을 읽는 방법을 먼저 시도했으나 실패했다.
> Electron은 창 제목을 메인 프로세스에서 관리해서 페이지가 바꿔도 반영되지 않는다.

`allow pasting` 은 평소에 건너뛴다. 타이핑해야 해서 1초 가까이 걸리는데, 한 번 허용하면
계속 유지되기 때문이다. 검증에 실패했을 때만 차단이 걸린 것으로 보고 풀어서 재시도한다.

`>` 접두어가 핵심이다. 이게 없으면 커맨드 메뉴는 명령이 아니라 **파일 검색**으로 동작해서
아무것도 실행되지 않는다. 접두어는 `>` 명령, `!` 스니펫, 없으면 파일 검색이다.

### 이미 넓으면 건너뛴다

적용이 끝난 뒤에도 자동 실행이 돌 때마다 오버레이가 뜨고 포커스를 뺏는 것이 제일 거슬린다.
그래서 손대기 전에 먼저 확인한다. **확인 자체는 화면을 띄우지 않는다.** 건너뛸 일이면
사용자는 아무것도 보지 못하고, 트레이 툴팁만 `이미 넓음` 으로 바뀐다.

두 앱의 확인 방법이 다르다.

| | 방법 | 성격 |
|---|---|---|
| ChatGPT | CDP로 `dataset.wideChatgpt` 를 읽는다 | 실제 관찰 |
| Claude | 적용에 성공한 프로세스의 신원과 비교한다 | 추론 |

Claude는 값을 읽으려면 DevTools를 열고 콘솔에 입력해야 해서 **확인 비용이 적용 비용과
같다.** 확인하는 순간 이미 화면이 뜬 뒤라 의미가 없다. 그래서 관찰 대신 추론한다.
적용에 성공하면 그때 Claude 프로세스의 PID와 시작 시각을 `WideAgent.claude.applied` 에
적어 두고, 다음에 같은 프로세스가 떠 있으면 아직 넓다고 본다. PID만으로는 부족하다.
번호는 재사용되므로 시작 시각을 같이 묶는다. 페이지의 MutationObserver가 앱의 되돌림을
막고 있으므로 그 프로세스가 사는 동안은 유지된다.

추론이라 틀릴 수 있다. 렌더러가 페이지를 다시 읽으면(앱 업데이트, 크래시 복구, 로그아웃)
관찰자가 사라져 기본값으로 돌아가는데 프로세스는 그대로다. 이때는 좁아진 것을 보고
트레이에서 직접 적용하면 된다. **사용자가 명시적으로 요청한 경우 - 트레이 메뉴,
아이콘 더블클릭 - 에는 이 건너뛰기를 적용하지 않는다.** 화면이 좁아 보여서 누른 것이므로
기록을 믿고 건너뛰면 안 된다.

#### 자동으로는 앱을 껐다 켜지 않는다

ChatGPT를 평범한 아이콘으로 열면 디버깅 연결이 없어서, 붙으려면 앱을 껐다 켜는
수밖에 없다. 그런데 사용자는 방금 ChatGPT를 열어서 쓰려는 참이다. 거기서 앱이
말없이 사라졌다 돌아오면 놀란다.

그래서 **자동으로 도는 경우에는 재시작하지 않는다.** 붙을 수 없으면 풍선 알림과
트레이 툴팁으로 알리기만 하고 물러난다. 애초에 `ChatGPT (Wide)` 바로가기로 열면
이 상황 자체가 생기지 않는다.

**알림 자체가 재시작 버튼이다.** 클릭하면 그 자리에서 다시 시작하고 넓힌다.
Windows 풍선 알림에는 버튼을 달 수 없지만 알림 본체는 클릭 대상이라
(`BalloonTipClicked`) 그것을 버튼으로 쓴다. 알림이 닫힐 때 제안을 지우지는 않는다.
시간이 지나 알림 센터로 넘어간 뒤에 눌러도 동작해야 하기 때문이다.

문구에는 **"직접 껐다 켜는 것으로는 넓어지지 않습니다"** 를 반드시 넣는다.
이게 없으면 '아 재시작하면 되는구나' 하고 평범한 아이콘으로 다시 열게 되는데,
그래도 플래그가 없으니 또 같은 알림이 뜬다. 그 반복에 빠지는 것이 이 알림의
제일 큰 위험이다. 근본 해결책인 바로가기도 **첫 알림부터** 같이 알린다.
두 번째부터 알려 봐야 한 번 겪을 일을 굳이 두 번 겪게 만들 뿐이다.

연결이 살아 있으면 얘기가 다르다. 그때는 키보드도 포커스도 쓰지 않으므로 오버레이
없이 조용히 끝낸다. ChatGPT 쪽에서 화면이 뜨는 경우는 사용자가 직접 요청했을 때뿐이다.

우리가 껐다 켠 직후에는 감지를 20초 쉰다. 재시작하는 동안 프로세스가 잠깐 사라졌다
돌아오는데, 감시 루프가 그것을 '사용자가 새로 실행함'으로 오해해 한 번 더 도는 것을
막기 위해서다.

#### Claude를 CDP로 바꾸지 않은 이유

ChatGPT처럼 Claude도 CDP로 붙이면 확인도 적용도 완전히 백그라운드가 되고, DevTools
키보드 주입 코드가 통째로 사라진다. Claude 데스크톱도 같은 MSIX + Electron 구조라
기술적으로는 아마 될 것이다. 그런데 `app.asar` 을 보면 이렇게 되어 있다.

```js
var dW = ["remote-debugging-port","remote-debugging-pipe","ignore-certificate-errors",
          "host-resolver-rules","host-rules","disable-web-security","log-net-log",
          "net-log-capture-mode","ssl-key-log-file","renderer-cmd-prefix", ...];
```

`--remote-debugging-port` 가 `disable-web-security` 와 같은 등급의 위험 스위치로 분류돼
있고, 이 플래그로 뜨면 `localPairingDisabledReason` 이 설정되어 **로컬 페어링이 꺼진다.**
정당한 CDP 접근을 위한 서명 토큰 경로(`CLAUDE_CDP_AUTH`, Ed25519 검증, 5분 만료)가
따로 있다는 것은, 그 밖의 경로는 의도적으로 막아 두었다는 뜻이다.

대화창 폭을 넓히자고 앱이 세워 둔 보안 통제를 우회하고 보안 기능을 끌 이유는 없다.
지금 쓰는 `allowDevTools` 는 사용자가 직접 켜는 공개 설정이라 성격이 다르다.
ChatGPT 쪽에는 이런 차단 목록이 없다.

### 진행 표시

DevTools 창은 화면 밖(가상 화면 오른쪽 바깥)으로 옮겨 두어 보이지 않는다.
대신 화면 한가운데에 오버레이가 떠서 어디까지 진행됐는지 알린다.
`WS_EX_NOACTIVATE` 창이라 포커스를 가져가지 않고 Alt+Tab에도 뜨지 않는다.

```
WideAgent
콘솔 여는 중
━━━━━━━━━━━──────────────────
키보드와 마우스를 건드리지 마세요
```

**적용 중에는 조작하면 안 된다.** 그래서 경고 문구를 띄우고, 끝나면 "이제 사용하셔도 됩니다"
로 바뀐다. 실패하면 빨간 글씨로 이유를 보여주고 2초쯤 머문다.

### 포커스 가드

중간에 다른 창을 클릭하면 남은 키 입력이 **그 프로그램으로 들어가 버린다.** 코드 한 덩어리가
엉뚱한 곳에 붙여넣어지는 셈이라 실패보다 이쪽이 위험하다.
그래서 매 입력 직전에 대상 창이 여전히 앞에 있는지 확인하고, 어긋나면 즉시 멈춘다.
멈춘 뒤에는 포커스를 되찾아 한 번만 다시 시도한다.

검증: 적용 도중(800ms, 1000ms 시점) 다른 창으로 포커스를 강제로 옮기는 시험에서
두 경우 모두 **유출된 글자 수 0**, 폴백으로 넘어가 정상 완료됐다.

포커스를 빼앗겨 실패한 경우는 실패로 끝내지 않는다. 상주 모드에서 **약 3초 뒤에 다시 시도하며,
최대 3번까지** 한다.

```
WideAgent · 재시도 (1/3)
곧 다시 시도합니다 · 2초
━━━━━━━━━━━──────────────────
키보드와 마우스를 건드리지 마세요
```

재시도 직전에는 2초간 카운트다운을 보여준다. 앞선 실패가 대개 사용자가 뭔가 하던 중이었기
때문에, 곧바로 포커스를 뺏지 않고 손을 뗄 시간을 준다.
3초는 실패 표시(0.8초) → 다음 점검(최대 1초) → 안내 카운트다운(2초) 를 합친 값이다.

세 번째까지 실패하면 물러나면서 다시 시도하는 방법을 알려 준다.

```
WideAgent
다른 창을 사용 중이라 중단됨
다시 시도하려면 트레이 아이콘을 더블클릭하세요
```

실패 사유도 하나로 모았다. 예전에는 같은 원인이 "DevTools가 열리지 않음",
"메인 창을 앞으로 가져오지 못함", "DevTools 창을 앞으로 가져오지 못함" 으로 흩어져 나왔고,
특히 첫 번째는 설정 파일 문제로 오인하게 만들면서 15초를 기다렸다.
지금은 포그라운드 창이 Claude 쪽인지 확인해 원인을 구분하고, 아니면 일찍 접는다.

> 입력을 아예 막는 `BlockInput` API도 있지만 쓰지 않았다. 적용 도중 프로그램이 죽으면
> 키보드와 마우스가 잠긴 채 남는다(Ctrl+Alt+Del로만 풀림). 경고만 하는 편이 안전하다.

**포커스 이동 자체는 피할 수 없다.** 다른 앱 창에 키를 보내려면 그 창이 포그라운드여야 하고,
`PostMessage` 로 합성한 입력은 Chromium이 무시한다. 그 8초 사이에 타이핑하면 입력이 엉킨다.
그래서 앱이 뜬 직후에 최대한 빨리 끝내도록 대기 시간을 줄여 두었다.

우리가 연 DevTools는 어떤 경로로 끝나든 `finally` 에서 반드시 닫는다.
화면 밖에 숨겨 둔 창이 남으면 사용자가 찾을 수도 닫을 수도 없기 때문이다.
닫기는 `WM_CLOSE` → `Alt+F4` → 화면 안으로 복귀 순으로 세 번 시도한다.

시작할 때 이미 DevTools가 열려 있으면 사용자가 연 것으로 보고 건드리지 않는다.
단 **화면 밖에 있는 창은 예외** 로, 화면 밖으로 옮기는 건 이 프로그램뿐이므로
이전 실행이 남긴 것으로 판단해 넘겨받아 닫는다.

텍스트는 타이핑이 아니라 클립보드 붙여넣기로 넣는다. 한글 IME가 켜져 있으면 한글로 들어가기 때문이다.
기존 클립보드 내용은 백업했다가 되돌린다. 유일하게 타이핑해야 하는 `allow pasting` 은
`imm32` 로 IME를 영문으로 돌린 뒤 입력한다.

## 전제 조건

**없다. 프로그램이 알아서 준비한다.**

DevTools를 열려면 앱 자체의 스위치가 켜져 있어야 한다. 처음 쓰는 사람은 당연히 꺼져 있으므로,
없으면 프로그램이 직접 만든다. 이미 있으면 건드리지 않고, 다른 내용이 들어 있으면 `.bak` 으로
백업한 뒤 쓴다.

```
C:\Users\<사용자>\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\developer_settings.json
```

```json
{ "allowDevTools": true }
```

앱은 이 파일을 단축키를 누를 때마다 새로 읽으므로 **Claude를 재시작할 필요가 없다.**
설정 폴더는 MSIX 가상 경로와 `%APPDATA%\Claude` 를 모두 살펴 `config.json` 이 있는 쪽을 고른다.
(예전 버전은 후자를 썼고 업데이트 때 전자로 이관됐다)

단축키는 `Ctrl+Shift+I` 가 아니라 **`Ctrl+Alt+I`** 다.

> **왜 DevTools 스니펫을 쓰지 않는가**
> 처음에는 `wide-chat` 이라는 이름으로 스니펫을 등록해 두고 그것을 실행했다.
> 그런데 앱이 1.40609 → 1.46388 로 업데이트되면서 앱 데이터가 MSIX 가상 경로로 이관됐고,
> DevTools 저장소에 있던 스니펫이 사라졌다. 그래서 코드를 실행 파일 안에 넣어
> 잃어버릴 외부 등록물이 없게 바꿨다. `src/snippet.js` 는 참고용으로만 남겨 둔다.

## 하지 않은 것

- **앱 패키지 수정**: 설치된 ChatGPT와 Claude 패키지는 수정하지 않는다. 업데이트 때마다 교체되기 때문이다.
- **외부 공개 디버깅 포트**: ChatGPT 연결은 `127.0.0.1` 루프백 주소에만 바인딩한다.
- **확장/플러그인** — DXT와 Claude Code 플러그인은 전부 MCP 서버라 렌더러에 CSS를 넣는 통로가 없다.

앱이 언젠가 `m`/`l` 을 정식 설정으로 열어주면 이 프로그램 전체가 필요 없어진다.
